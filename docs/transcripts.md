# Session transcripts

Every session's full Agent SDK transcript (the JSONL the SDK writes to `~/.claude/projects/<cwd slug>/<sdkSessionId>.jsonl`: each prompt, tool call, tool output and token count) is kept by the town, keyed by town session id. Asked for in the 1:1 between Mitchell and Pix after the memory retro (dc_xc7zaa1gwc, section 1), so retros can read what every agent did, not only the agent running the retro.

- **Desks** (`packages/desk/src/run.ts`): after the query ends and before session-end, the desk reads the JSONL of every SDK session it ran (two after an API-key failover, joined in order), compresses it with brotli and posts it to `POST /api/agents/me/transcript?session=<id>` (`Content-Type: application/x-brotli`, ≤ 24 MB compressed, ≤ 64 MB raw). Best effort: a failed upload is logged and the session ends as usual. The desk code is in the desk image, so this needs a redeploy with `image: true`.
- **Host sessions** (`runAgentSession` in `packages/runtime/src/session.ts`: manage and 1:1s, meeting replies, facilitation, host work): the runtime reads the JSONL from `$CLAUDE_CONFIG_DIR` or `~/.claude` on the server and stores it the same way. One-shot calls (standup summaries, chat asks) run with `persistSession: false` and have none.
- **Storage** (`packages/core/src/transcripts.ts`, migration 044): one `transcripts` row per session (sizes, line count, source desk|host) and a brotli file `<data>/transcripts/<sessionId>.jsonl.br` beside `town.db`. Not in the database, so the nightly backup doesn't carry them: at ~200 sessions a day that would add gigabytes. A later upload replaces the earlier one.
- **Retention**: `desks.transcriptDays` in collective.json (default 90). Rows and files older than that are removed at most once an hour, on the next store.
- **Reading**: `GET /api/sessions/<id>/transcript` returns the JSONL as text (`?download=1` saves it); `GET /api/sessions/<id>` returns the session and, for a permitted reader, `transcript` (bytes, lines, expiresAt, url). Readers: admins, managers of the session's building (the agent's home, or the meeting's building), and the session's own agent. Everyone else gets 403.
- **Web**: the Session row in an agent's Talk tab shows a `transcript` link for permitted readers.

## Live view of a running fork: `fork_status`

The kept transcript exists only once a session ends. For a fork still running, the manager (or a reviewer, `building.assign` on the fork's building, or anyone who may read its transcript) calls the town verb `fork_status` with `forkId` or `assignmentId` (`packages/core/src/forkstatus.ts`; agent teams step 2, dc_i7ji4xacd9). It returns the assignment (title, id, lane), the session's start and minutes, adjusted output tokens booked so far, the latest thought, and the last `limit` (default 10) tool calls: the `agent.tool` events of the live session with the first line of each input and a one-line result. Results come from `world.toolResults`, an in-memory ring fed by host sessions (tool_result blocks) and desks (`POST /api/agents/me/activity` kind `result` with `toolUseId`); they are not stored, so after a restart, or from a desk image older than this change, a call shows `result: null`.
