# Muster Town — architecture contract (v1.4)

This is the build contract. `packages/schema/src/index.ts` is the type-level source of truth; this document explains how the pieces fit, who owns what, and the behaviors that aren't expressible in types. If code and this document disagree, fix one of them in the same commit.

The body describes the town as built at v1.4. The v1.1 desk contract is the **Desks** section; what each version changed is in **Change history** at the end.

Tagline: publicly legible, collectively funded agent town for climate science.

Name: the software was renamed Agent Town → Muster Town on 2026-10-20. Env vars are `MUSTER_TOWN_*`; each one falls back to its old `AGENT_TOWN_*` name when unset, and CLI profiles fall back from `~/.muster-town/` to `~/.agent-town/`, until the cleanup phase drops the fallbacks. The desk image (`muster-town-desk`, also tagged `agent-town-desk`), its bin (`muster-town-desk`, alias `agent-town-desk`) and new desks' container labels (`muster-town.*`) use the new name; the runtime still execs the old bin name and sweeps both label prefixes so desks built before the rename keep working.

## Map: the system in 10 minutes

Read this section first. It shows the four core subsystems (runtime and wakes, assignments and lanes, grants, the Bank), the stores they share and the API they're reached through, and where each one lives in the code. The rest of the document is the detailed contract.

### The pieces

| Subsystem | What it does | Code |
|---|---|---|

### How work flows

A human asks for something, it becomes an assignment, the runtime wakes an agent, the session ends in a report, and the report goes up through the in-tray to a rollup that a human decides.

```mermaid
flowchart TD
  human([Human]) -->|"1:1, tell, flag, review<br/>(REST: routes/)"| mgr
  subgraph assign["Assignments & lanes (core/domain.ts, core/lanes.ts)"]
    mgr["Manager agent<br/>assign / review / meeting decide"] -->|"createAssignment + resolveLane<br/>(grant · exploration · directed)"| queue[("assignments<br/>pending queue")]
  end
  subgraph rt["Runtime & wakes (runtime/index.ts, runtime/waker.ts)"]
    tick["tick every 5 s<br/>scheduleWork"] -->|"nextStartable → Budget.canStart<br/>(building budget, cap hold, lane gate)"| start["startWork"]
    explore["exploreTick (core/explore.ts)<br/>explore rule · free tokens · idle desk"] -->|"reserve a chunk (bank_reservations)<br/>+ exploration assignment"| queue
    waker["Waker over the event log<br/>WAKE_RULES"] -->|"doc.created report / flag"| wm["wakeManager<br/>(manage session)"]
  end
  queue --> tick
  start --> session["Work session<br/>desk container or host<br/>(desk/run.ts, runtime/work.ts)"]
  session -->|"MCP verbs (server/mcp.ts)"| verbs["core verbs"]
  session -->|"submit_report"| report[("report doc<br/>decision: pending")]
  report -->|"building in-tray (intrayOf)"| waker
  wm --> mgr
  mgr -->|"submit_report rollup: true"| townhall[["Town Hall in-tray<br/>rollups · grant proposals · checkpoints"]]
  townhall --> human
  verbs -.->|"every change appends"| events[("events log")]
  events -.-> waker
```

Where to look for each arrow:

- **Human → manager.** Humans talk to a building's manager agent in a 1:1; there is no direct message from the UI to an agent (the message composer, the `Message from …` assignment and the proxy chat were removed, 1:1 mt_wql34b8gkl). The Town Hall's manager is the Planner (`Reorgs.ensurePlanner`), in name only: `managerAgentOf` leaves the Town Hall out, so its in-tray stays the humans' and the Planner answers 1:1s and facilitates reorgs. 1:1s wake the manager through the `manager-1:1` rule in `packages/runtime/src/waker.ts`. A flag (`POST /api/buildings/:id/flags`) lands in the in-tray like a report.
- **Manager → assignment.** `assign`, `review` continue/redirect and meeting decisions all go through `createAssignment` (`packages/core/src/domain.ts`), which calls `resolveLane` (`packages/core/src/lanes.ts`). Every lab is goal-directed (`laneGated`: every building but the Town Hall; the old `open` budget mode is gone): agent-created work must name a funded grant (its key results are implied), a goal gap (exploration), or a human source (`directed`, checked by `humanSource`).
- **Assignment → session.** Only the scheduler starts work: `scheduleWork` in `packages/runtime/src/index.ts` takes `nextStartable` (`packages/core/src/domain.ts`), which skips what `Budget.canStart` holds. A held assignment stays pending with a `heldReason`; it's never cancelled. `waitFor` holds are checked by `checkWaits` (`packages/core/src/waits.ts`) on the same tick.
- **Session → report.** A desk session fetches its brief (`GET /api/agents/me/brief`, prompts from `packages/core/src/prompts.ts`), calls verbs over MCP, and posts `session-end` (`packages/server/src/routes/desk.ts`). `finishWorkSession` (`packages/runtime/src/work.ts`) writes a fallback report if none was submitted, so every session ends in a report.
- **Report → in-tray → rollup.** `submit_report` (`packages/core/src/verbs/docs.ts`) puts the report in the building's in-tray and makes the agent idle. The `manager-intray` wake rule starts or feeds the manager's manage session (`wakeManager`, `packages/runtime/src/manage.ts`), which decides each report with `review`. The manager reaches humans only through a rollup (`rollup: true`), grant proposals and checkpoints, which `townHallIntray` (`packages/core/src/domain.ts`) collects for the Town Hall.

### How tokens flow

A human funds a grant, its work runs in lane `grant`, and every session's usage is charged to the Bank and counted against the grant.

```mermaid
flowchart LR
  subgraph bank["Bank (core/bank.ts)"]
    inputs["Bank inputs<br/>subscription · API key"] -->|"creditDue (tick)"| pools[("one balance<br/>bank_credits − bank_debits")]
  end
  subgraph grants["Grants (core/grants.ts)"]
    propose["propose_grant<br/>(manager)"] --> decide{"human decides<br/>Grants.decide"}
    decide -->|fund| funded["grant: funded"]
    funded -->|"spent ≥ grantTokens<br/>Grants.checkpoints"| checkpoint["grant: checkpoint<br/>+ checkpoint assignment"]
    checkpoint -->|"continue / adjust"| funded
    checkpoint -->|cut| closed["closed"]
  end
  decide -->|"fund → front-of-queue assignment<br/>for the manager (lane grant)"| asg[("assignment<br/>lane · grantId")]
  asg -->|"laneHold: grant funded?<br/>free tokens? under the goal's cap?"| gate["Budget.canStart"]
  gate --> sess["session<br/>(lane, grantId copied from the assignment)"]
  pools -->|"fundingFor: which key / allocation pays"| sess
  sess -->|"finishWorkSession → chargeUsage<br/>→ Budget.charge → Bank.drawTokens"| pools
  sess -->|"Grants.spent = sum of the<br/>grant's sessions (adjusted tokens)"| funded
```

- **Funding a session.** `fundingForSession` (`packages/runtime/src/session.ts`) asks `Budget.fundingFor` (`packages/core/src/budget.ts`), the one chooser every SDK call goes through, for exactly one credential in draw order: the grant's own input (`fundedWith`), the nearest earmark up from the work's goal (`Streams.pick`, `packages/core/src/streams.ts`), then the general balance (a subscription allocation, the Bank's share, other allocations, the town credential). Nothing that can run it throws `NoCredential` and the building is held.
- **Charging.** A session is debited as it runs (`bookRunning`, at most once a minute, from the host's `UsageMeter` or the desk's `usage` activity posts) and trued up at its end (`endAndCharge`), however it ends (docs/invariants/bank.md 13). Each booking → `Budget.charge` (`packages/core/src/budget.ts`) records the five token counters on the agent and draws them from the building's Bank share (`Bank.drawTokens`) or an allocation. Figures are in **adjusted output tokens** (`adjustedOutputTokens` in `packages/core/src/bank.ts`; the pricing is explained in `docs/bank.md`).
- **Metering a grant.** A session copies its assignment's `lane` and `grantId` when it starts (`packages/core/src/ops.ts`), and `Grants.spent` sums those sessions. After each charge, `Budget.afterCharge` runs `Grants.checkpoints` (wired in `packages/core/src/world.ts`). It moves a grant whose spend reached its tokens to `checkpoint` and queues the manager's checkpoint assignment. `laneBlock` then holds the grant's other work until a human continues, adjusts or cuts it.
- **Exploration.** There is no allowance (docs/how-work-gets-done.md §8). The runtime tick's `exploreTick` (`packages/core/src/explore.ts`) starts one explorer per idle building when its goal's explore rule is on (`explore`, `exploreChunkTokens`, default 100,000), a desk is free, the building's queue has nothing startable, it has no open proposal or reservation and none opened in 30 min, and free tokens cover the chunk under the goal's optional `exploreCapTokensPerDay`. It opens a `bank_reservations` row (which counts against free tokens while open, less what its sessions spent) and an exploration assignment carrying `reservationId`; at 90% of the chunk the explorer is asked once to file, and its brief ends with one `propose_grant`. The reservation closes once the assignment ends, returning the unspent part (events `exploration.reserved`, `.started`, `.proposed`, `.closed`). Other exploration is held only with no free tokens under its goal or at the cap (`laneBlock`). Directed work is metered on its own (`Grants.directed`).

### Shared stores

All state is in one SQLite database (`MUSTER_TOWN_DATA/town.db`). Each table is behind a repository on `World` (`world.agents`, `world.assignments`, …), and every schema change is a numbered file in `packages/core/migrations/`. The tables the four subsystems share:

| Table | Written by | Read by |
|---|---|---|

| `assignments` | `createAssignment`, `applyDecision`, grant decisions and checkpoints, wakes | the scheduler, the lane gate, the desk brief |
| `schedules` | `createSchedule` (the `schedule` tool, POST /api/buildings/:id/schedules), `fireSchedules` on the tick (docs/scheduling.md) | `fireSchedules` (creates assignments), /api/scheduled, the building Overview, the manager's team block |
| `sessions` | the runtime (`ops.startSession` / `ops.endSession`) | `Grants.spent`, the Bank's drift job, reports' token stamps |

| `grants` (`goalId`), `key_results` (`grantId`: a grant's 1–5 key results; goal key results without a grant were archived by migration 069), `objectives` | `Grants` (`propose_grant` with `goalId` + `keyResults`, `checkpoint_grant`, `close_grant`, human REST) | the lane gate, the board, the desk brief |
| `goals` (`explore`, `exploreChunkTokens`, `exploreCapTokensPerDay`, inherited), `goal_proposals`, `goal_changes`, `goal_captain_requests` ("Ask to captain", `packages/core/src/captain.ts`), `buildings.goalId` | `Goals` (`packages/core/src/goals.ts`; REST `packages/server/src/routes/goals.ts`; verbs `propose_goal`; `set_key_result` and `propose_key_result` are deleted, migration 069) | `Goals.inScope` for grants and lanes, the desk brief, the in-tray routing, the goal history API for agents (`Goals.history`; not shown in the web since 1:1 mt_n25udpflus decision 5); the web editor is the Town Hall `goal-tree` place → `GoalTreePanel.tsx`; "Change this goal" and the Planner are `Reorgs` (`packages/core/src/goal-changes.ts`, `world.reorgs`); postmortems on missed key results are `packages/core/src/postmortems.ts`, the building Queue tab (kanban; the goal board is API-only) `packages/core/src/kanban.ts` (design: [docs/goals.md](goals.md)) |

Live state is never stored in git: `world.export()` (`packages/core/src/export.ts`) writes a readable mirror once an hour.

## World model

- Grid of 16px tiles. **The map is the goal tree** (docs/goals.md "The map is the tree", build step 2): nobody places buildings. `core/world/tree.ts` `treeLayout(goals, buildings)` computes every lot and plaza from the active goals: the **Town Hall** (kind `town-hall`) stands at the root above the root plaza, the Bank (fixed `BANK_LOT`) below it; each goal is a **plaza** (a road strip two tiles tall with a `TILE.SIGNPOST` at its right end, place `plaza:<goalId>` named with the goal's words; the root's also keeps the old id `plaza`); each lab hangs below the plaza of the goal it is attached to (`buildings.goalId`), door in its top wall on the plaza, left to right in creation order; a goal's children hang below its cluster, left to right by `position`, `createdAt`, id. Each subtree owns a band of columns rounded up to `BAND_STEP` (8), so adding a child moves nothing to its left and usually nothing at all. An empty goal (no building, e.g. Fund/Join/Trust) is an empty plaza with its signpost. A lab's size is `labSize(headcount)`: its **Desks** setting (PATCH `headcount`, `town.manage_buildings`) is the size control. Roads are derived (`core/world/road.ts` `deriveRoads`, nothing stored): the plazas, the tree's edges drawn like an org chart (`treeLayout`'s `edges`: a trunk down the parent's left corridor, a bus above its children, a drop onto each child's plaza; the layout keeps those tiles free), and a road from each door (and the Bank's) to its own plaza found by a grid Dijkstra (turns cost 4), empty since every doorstep is on its plaza. `computeLayout(buildings, goals, occupancy, names)` draws it all; `WorldMap.rebuild` stores each building's lot and, when the tree moved lots or places, calls `follow` (`entities.ts` `followRelayout`): bodies inside a moved building move with it, bodies at moved places and seats go to the new tiles, anyone a building now covers steps to the nearest free tile, walks re-plan. A World event hook rebuilds on every tree change (`goal.created`, `goal.edited`, `goal.moved`, `goal.retired`, `goal.attached`). Furniture inside a lot is a list of pieces (`core/world/furniture.ts`: footprint cells, stand tiles, a default anchor relative to the lot); a lab's room is the Town Hall-style room mirrored top-to-bottom (`facesNorth(kind)`: its door is in the top wall, its board on the bottom wall). `Building.furniture` stores only moved pieces' anchors, and a stored anchor that is no longer legal (e.g. after a resize) falls back to the default. `validateLayout(kind, lot, pieces, anchors)` is the one rule set: inside the room (wall pieces on a side wall or the back wall), nothing on or just inside the door, no overlaps, stand tiles free and unshared, every stand tile and 2 seats per table reachable from the door. Humans with `building.manage` (the Town Hall: the admin) rearrange rooms in the web client's Edit layout mode; agents can't. **The town map** (the Town Hall map table, anyone): the camera zooms out to the whole town (the same overview as the Bank's town map, `renderer.overview()`), read-only; clicking a building selects it and the side bar shows "Attached to: [goal path] · Change…" (opens its Settings), its budget and stats.
- Inside a lab: desks in rows (each desk = 2 tiles wide, agent stands below it), a meeting room area (table) at the bottom-right (every walkable tile touching a meeting table is a seat: `go` to a `meeting-room:*` place, or walking there for a meeting, takes the first seat no other body is on or headed for, the place's own tile first), a door at bottom center. Each desk is a Place `desk:<agentId>` once an agent occupies it; free desks are `desk:free:<buildingId>:<n>`. Each lab also has `board:<buildingId>` (kind `board`, a wall tile on the top wall: the building's board), `cabinet:<buildingId>` (kind `cabinet`, `TILE.CABINET` on the floor against the right wall, between the in-tray and the meeting table (bottom-right corner in one-row labs); stand to its left: the filing cabinet) and `intray:<buildingId>` (kind `intray`, the **manager's desk**, `TILE.MANAGER_DESK`, top-right: the building's pending reports). Reviewer agents sit at ordinary resident desks.
- Town Hall contains places: `library` (shelves), `town-map` (kind `town-map`, `TILE.TOWN_MAP`: the 5x2 map table where the trophy cases were; E or a click opens the read-only town map), `outbox` (counter), `meeting-room:town-hall`, `mod-station` (kind `mod-station`; town moderators have seats there as `desk:<agentId>`), `planning-desk` (kind `planning`: buildings, residents, roles, secrets, system; town planning is not here, it is the map table), `schedule-board` (kind `schedule`: upcoming meetings for every building), and its door. Outside: `plaza` on the main street in front of Town Hall. The **Bank** is a fixed landmark below the main street, under the Town Hall (`BANK_LOT`/`BANK_FIXTURES` in schema; not a building row, so it never takes a budget share): gold walls, marble floor, `TILE.PILLAR`/`GOLD`/`VAULT`. The Bank panel is in tabs and every tab is a thing in the room (Mitchell, 1:1 mt_ew2d0mm7h9; no teller counter): the vault's stand is the place `bank` (Overview: balance, next 30 days, contributors, Donate), and each of `BANK_FIXTURES.stations` is a place `bank:<slug>` (kind `bank`; `bankTabOf` gives its tab): ledger desk → Tokens & sources (tokens, Bank inputs, sources), pools fountain → Pools (pool shares and balances), spending board → Spending (building funding, spending, Spend by goal: a goal's subtree from session rows via `GET /api/goals/:id/spend`, drift, out-of-tokens deaths and the cap), server rack → Hosting (Fly.io). The HUD's "$", `#/bank` and `#/finance` open Overview. The town map stand is `bank-map` (`TILE.BANK_MAP`). Right of the Town Hall, above the main street, the web hangs a marquee with `GET /api/bank`: total available tokens, then claimed (open reservations + open proposals' asks + funded grants' remaining, from `free`) and free (`free.freeTokens`) (refetched on `bank.*` events, spends, and every minute).
- Snapshot `places` includes all of these and `look` lists them, so agents can `go` to the board or the in-tray too. Retired agents are not in the snapshot and are not drawn.
- Movement: `go` computes a BFS path on walkable tiles (`WALKABLE` in schema; agents' bodies don't block) and the tick loop (10 Hz) advances the body at 8 tiles/s, emitting `agents.pos` batches to WS clients at most 10/s. `go` resolves when the body arrives (timeout 30 s → error). Humans move client-side and send `human.move`; the server validates walkability and broadcasts.
- Proximity: `say` and `look` use Chebyshev distance ≤ 3 tiles.
- Residents idle at their desk. After `go` elsewhere, a resident's next session start walks it back to its desk automatically.

## Store (core)

SQLite via better-sqlite3, WAL mode, file at `MUSTER_TOWN_DATA/town.db` (default `./data/town.db`). Tables mirror the schema objects one-to-one: `users`, `roles`, `memberships`, `buildings`, `allocations`, `agents`, `places` (derived, rebuilt on layout change), `docs` (+ FTS5 virtual table `docs_fts` on title+body), `assignments`, `messages`, `meetings`, `sessions`, `events` (append-only, autoincrement id), `tokens` (auth tokens: `{token, kind: 'user'|'agent', id, createdAt}`). JSON columns for nested fields (provenance, summaries, transcript, decisions, meetings cadence, lot). Migrations: a `schema_version` table and numbered SQL files applied at open. Adding a migration doesn't require editing `packages/core/test/v12.test.ts`: its v1.1 DB is built forward (migrations 001–004 plus SQL fixtures), and `World.open` applies every later one.

`core` exposes a `World` class: `open(path)`, repositories (`world.agents.get/list/upsert`, etc.), `world.events.append(...)` (which also calls subscribers), `world.verbs.<name>(actor, input)`, `world.permissions.can(holder, permission, buildingId?)` (v1.5, agents: `owner ? (ownRoles || inheritsOwner && ownerCan) && ownerCan : ownRoles`, minus `deniedPermissions`; an agent never exceeds its owner user; visitors and avatars inherit by default, residents and service agents don't; `permissions.effective(holder, buildingId?)` lists them), `world.budget.charge(agentId, tokens, usd)` (charges agent, building allocation, and emits `budget.exhausted` when a resident's daily or the building's allocation runs out), `world.layout.rebuild()`, `world.tick(dtMs)`, `world.export(dir)`, `world.importV0(dir)`.

## Verbs (core/verbs)

One function per verb in `VerbInputs`, signature `(world, actor: Agent, input) => Promise<result>`. Behaviors:

- `look` → `LookResult`. Nearby includes humans (kind `human`) so agents can see people. Its `town` line points at `town`.
- `town` (presence, 1:1 mt_3jtclcoxl2; core `verbs/social.ts`): every building, Town Hall first, with id, name, manager (name, id, status; the Town Hall's is the Planner), the attached goal (one line), live forks, and who stands in it now (non-offline agents and humans whose `buildingId` is it, 12 named then a count), plus everyone `in-meeting`; `query` filters by building or manager name/id. Every work brief carries `buildingsLine` (core `prompts.ts`): each other building → its manager's name and id. `tell` with a building id as `to` goes to its manager.
- `say` → event `agent.said`; delivered as `heard` messages to the inboxes of nearby agents (not humans; humans see the event live).
- `tell` → message `tell`; if the recipient is a human avatar, the UI shows it as a chat bubble/notification.
- `write` → creates/updates a doc; authorId = actor; state `building` requires `doc.write_building` in the actor's building; `type: 'source'` docs are the provenance targets and, once published, land in state `library` directly (references, not claims). Returns `{id}`.
- `submit_report` → doc type `report`, state `building`, verdict, decision `pending`. Links `assignmentId` (current) and marks the assignment `done`. **Hub semantics:** the report goes to the building's **in-tray** (its pending reports) and the agent goes `idle`; it works again only when someone gives it an assignment (a decision on the report, meeting decision, `assign`). **Who works an in-tray is derived, not a setting** (migration 029 dropped `reviewPolicy`; `docs/waterfall.md` §3.1): `managerAgentOf(building)` is the building's `managerAgentId` when that is a resident not stopped/banned/retired, and then the manager works the in-tray (`intrayWorker` = `manager`), else a human does. Rollups are **Town Hall in-tray** items (`isTownHallItem`, by the `rollup` tag, not the author: `rollup: true`, managers only, covered reports required in `provenance.sourceIds`; a checkpoint report is a rollup). A manager's own work report (a self-assignment, decision 6 of the 2026-10-25 town hall; or meeting-decided work) is an ordinary building in-tray item the manager itself decides in its next team-lead session. `GET /api/buildings/town-hall/intray` → `{ reports, grants }` (grants = proposed / countered / checkpoint town-wide); the Town Hall's badge count (`intrayCount`) is both. `review` refuses an agent deciding its own report, except a manager deciding its own work report (never its own rollup). A resident's report in a building with a manager agent notifies agents only (`notifyMentions` `agentsOnly`): humans get no notice for reports a manager consumes (decision 1d); the HUD lists in-tray counts only for buildings a human works plus the Town Hall. Every manager session gets `managerIntrayBlock` ("## Your in-tray": pending resident reports, the decision verbs, the escalation criteria, the rollup rule with the last rollup's time). The runtime ends the session after this verb. A session that ends without `submit_report` gets a fallback report written by the runtime (verdict continue, body = final message), so the invariant "every session ends in a report" holds.
- `review` → requires `building.review`; the report must be pending. Sets decision/note/decidedBy (`core/domain.ts` `applyDecision`):
  - `approve` = acknowledged. No assignment is created (UI label "Acknowledge").
  - `continue` = acknowledged + an assignment from the report's "Proposal" section (title = first line of the proposal, description = proposal + note).
  - `redirect` = acknowledged + an assignment from the decider's note (note required; the proposal is appended as context).
  - `stop` = acknowledged; the agent's pending/active assignments are cancelled and its status becomes `stopped`.
  Humans call the same code via REST.
- `assign` → requires `building.assign` in the target's home building; creates a pending assignment and messages the agent (optional `waitFor`, see Waiting assignments). `assignments` lists mine; `accept_assignment` makes a pending assignment my current one.
- `promote` → requires `building.promote`; moves a doc to state `building` or `library`.
- `ban` → requires `town.ban` (town moderators, admin).
- `redeploy` (`{ image?: boolean }`, default false) → requires `town.redeploy` (town `deployer`, admin, or, outside a hosted collective, any building manager and its live forks: town hall mt_e1uoil9mx5 decision 1). Calls the host hook the runtime registers on `world.host.redeploy` (see Redeploy); without a runtime it fails as unavailable. Returns `{ started: true }`, or `{ queued: true }` while one is in flight (the request joins it; see Redeploy).
- `request_human` → doc type `request`, state `building`, `requestStatus: open`, visible at once in the Town Hall outbox (no approval step; migration 045 opened every old `proposed`/`approved` one, and the schema reads those values as `open`). Any human decides whether to do it. A moderator (`town.approve_request`, now meaning "delete a request") can delete one that misuses the town; the requester is told. Humans claim and submit `human-report` docs via REST; those land in the library as sources (state `library`).
- **Skills** (docs/skills.md): DocType `skill`, body = SKILL.md (frontmatter `name` + `description`, name unique town-wide = the title), bundled text files in `skill_files`, pins in `skill_pins` (scope agent/building/town, mode listed/always). Verbs `skills` and `pin`; `write` takes `files` for skills, `read` lists them and takes `file`; every skill read appends `skill.used`. Pins into others' sessions that are `always`, town-wide, or of a skill with files need a human; an agent-made pin is suspended if files are added later. `skillsBlock` (core) puts pinned skills into every work system prompt (desk and in-process), always-on text capped at 8,000 chars. REST: `/api/skills`, `/api/skills/:id{,/bundle,/files/*,/pins}`, `DELETE /api/skill-pins/:id`; web: the library's Skills tab and a skill's files and pins under its doc.
- `meeting` → see Meetings. A meeting decision that assigns work to an agent acknowledges (`approve`, noted as superseded) that agent's pending reports, so every report still gets a decision.
- Permission errors throw `{code: 'forbidden', permission}`; the MCP layer returns them as tool errors with a readable message.

## Permissions & roles

Discord-style. A role has permissions and a scope; the built-in sets are `BUILTIN_ROLES` in schema. `can(holder, permission, buildingId?)` = any held role with that permission whose scope is town, or whose scope is building and `buildingId` matches.

- Town-scoped built-ins: `admin` (everything), `moderator` (`town.approve_request`, `town.ban`, `town.moderate`: collective-wide misuse prevention, seated at the mod station), `visitor`, `deployer` (`town.redeploy` only; the Town Workshop's residents hold it; building managers and their forks hold `town.redeploy` without it except in a hosted collective).
- Building-scoped built-ins, created with the building: `manager` (`building.manage`, `building.assign`, `building.review`, `building.promote`, `building.dismiss`, `doc.write_building`, `doc.request_human`, `meeting.facilitate`, `meeting.attend`), `reviewer` (`building.review`, `building.assign`, `meeting.facilitate`, `meeting.attend`, `doc.write_building`: a second pair of eyes that may decide reports; nothing is scheduled from it), `member` (`doc.write_building`, `doc.request_human`, `meeting.attend`).
- There is no building-level ban: ban is a town act (`town.ban`).

The first user (created at seed, name from `MUSTER_TOWN_ADMIN_NAME`, default "Mitchell") gets `admin`; their token is written to `data/admin-token` (0600); startup prints the path, never the token. Residents get `member` in their home building. The building creator gets `manager`. Agents and users can both hold roles (a building's reviewer agent holds `reviewer`; town moderator agents hold town `moderator`). `core/migrate-roles.ts` upgrades pre-v1.2 databases (building `moderator` → `reviewer`, creates town `moderator`, adds `building.dismiss` to managers) and, for v1.3, creates the town `deployer` role; in the pass that creates it, residents of buildings with code access (not reviewers, retired or banned agents) are granted it once, so a later revoke sticks. Seed grants `role:<name>` for each name in a collective resident's `townRoles`.

## Budgets

Users donate tokens (`DonateInput`) into an allocation for a building, optionally with their own Anthropic API key (stored in `users.apiKey`, never returned by the API). A building's spendable budget is the sum of its allocations' remaining tokens. The runtime picks the allocation to charge (oldest with remaining tokens) and, if that allocation's user has an API key, runs the session with `env.ANTHROPIC_API_KEY` set to it; otherwise the server's own login (Claude Code) is used. Session usage (input+output+cache tokens, cost from the SDK result) is charged after each session. A resident whose building's budget is exhausted goes `out-of-budget` and won't start sessions until a new allocation. Seed creates a large allocation ("house budget", 50M tokens) for the Carbon Cycle Lab so local dev isn't blocked. `dailyTokensPerAgent` is still stored but read by nothing: the per-agent and family daily caps were deleted on 2026-10-31 (1:1 mt_q10xf3bkoq).

**Town Bank** (`world.bank`; steps 1-2: inputs, balance, building shares). A `BankInput` is {label, source `api-key` | `subscription`, model, tokens, recurrence `once` | `daily` | `weekly` | `monthly`, `nextCreditAt`}; its API key sits in the secret `bank_inputs.apiKey` column. A one-time input credits once when added; a recurring one credits `tokens` only when `nextCreditAt` is due, then moves it one period on (past now, so downtime never pays twice). A `subscription` is the town owner's own plan only (admin; pooling other people's subscriptions isn't allowed): daily, crediting min(tokens, `weeklyCapTokens` minus what it credited in the last 7 days). Each credit is a `bank_credits` row and a `bank.credited` event. A subscription credit is *expiring*: `expiresAt` is the next daily renewal, so unused quota doesn't roll over; an API-key credit is *durable* (`expiresAt` null). The runtime calls `bank.creditDue()` every tick. **Calibration (Bank grant step 4, `core/src/drift.ts`):** the runtime also calls `bank.driftDue()` every tick; once per UTC day it runs the drift job for the day before: per model and building (and per model over all buildings), the ended sessions' adjusted output tokens × that model's output list price (`TOKEN_PRICES`) against the SDK's `costUsd`, one `bank.drift` event per row {day, model, building, sessions, backfilled, adjustedOutputTokens, adjustedUsd, costUsd, ratio = adjustedUsd / costUsd} (back-filled sessions, whose counters are just the raw split, are counted in `backfilled` and left out; a day with no sessions writes one marker row, model null). GET /api/bank `drift` gives the latest run and the Bank page shows "drift: 0.97 (24 h)" per model. A session the desk classified as `SPEND_LIMIT` (it posts the SDK's message as `spendLimit` at session end, the session ends on it; there is no in-session failover since 2026-10-30, the next session runs on the Bank's key), or whose error reads like one, logs `bank.cap` next to `session.ended` {sessionId, building, input (the subscription input), day, adjustedSpendToday, subscriptionAdjustedToday, listUsdToday, sessionsToday, funding, message, resetsAt (a UTC time of day in the message, else null)}.

**Token usage** (migration 024). Every charge writes a `usage` ledger row (`{id, agentId, buildingId, tokens, usd, createdAt}`, `buildingId` = the agent's home) via `budget.recordUsage`, whether or not anything funded it (`budget.charge` calls it; the runtime calls it alone only for an agent with no building: a building with nothing left is debited anyway, overshooting). `budget.usage(buildingId)` sums it: `tokensToday` since the server's local midnight (when daily allowances reset) and `tokensAllTime`; both ride on every `BuildingBudget` (snapshot, WS `building`, `GET /api/buildings/:id` `budget`, `GET /api/budget`). The migration back-filled the ledger from the agents' `spentTokensTotal` / `spentTokensToday`.

**One balance, no pools** (how-work-gets-done.md build step 1, migration 067; pools were Bank step 2, migration 023). Every building (the Town Hall included: it pays the Planner, 1:1 mt_cz11aqe81a) draws the one general balance first come first served: each unexpired expiring credit less what was drawn from it, plus all durable credits less durable draws (`bank.available(buildingId)`); earmarked credits are outside it. Draws are `bank_debits` rows (`buildingId` who spent; `creditId` set for expiring, null for durable; the old `poolId` column keeps its default, read by nothing). `budget.charge` (no explicit allocation) draws expiring credits soonest-to-expire first, then durable, then the oldest allocation; whatever is still left overshoots (onto the allocation, else the durable balance goes negative and is paid back from later credits). There is no hard stop: sessions finish and are charged afterwards. There is no per-agent or family daily cap (deleted 2026-10-31, 1:1 mt_q10xf3bkoq). A building's `budget.remainingTokens` includes `bankTokens`, so `canStart` counts the Bank. `fundingFor` in the runtime: expiring tokens run on the subscription input's token; durable ones on the oldest live API-key input's key; otherwise the oldest allocation and its donor's key. **Free tokens** (`core/src/free-tokens.ts`) and the optional per-goal exploration cap: docs/goals.md "Free tokens and the optional exploration cap". The five token counters every Bank row keeps (grant gr_iq5m7dug56, migration 034) and the back-fill rule: docs/bank.md.

**Town map** (web `map/flow.ts`). The Bank has a map stand (`TILE.BANK_MAP`, place kind `bank-map`); E on it calls `MapRenderer.openFlow()`: the camera eases out to fit the whole town (`fitZoom`, never past the walking zoom), the town dims, and gold arcs run from the Bank to every building, each as wide as `widthFor(pct)` with coins in flight in proportion to its share, labelled with its % and the tokens it can still draw, under a card with the balance (expiring/durable) from `GET /api/bank`. Esc, E or walking puts the camera back. The arcs start at the `bank-map` place (else a `bank` place, else the Town Hall).

**Minimap and the shared overview** (web `map/overview.ts`, `map/Minimap.tsx`). `overview.ts` is the one zoomed-out renderer: `OverviewCam` (centre + zoom, `fit`, `clamp`, screen↔world↔tile) and `drawOverview` (the world bitmap shrunk, building names, people as status-coloured dots, an optional frame and hovered tile/building); `fitZoom` lives there too and frames the Bank's town map. Town planning draws through it as well. The minimap (bottom left, hidden under 760 px and while the town map or a layout edit is open) follows you; drag pans, the wheel zooms (1–6× the whole-town fit), ◎ snaps back. A click calls `MapRenderer.walkToTile`: `quickWalkGoal` walks to the tile if it's reachable, a building's wall walks to its door (the Bank's: its counter), anything else to the nearest reachable tile; long routes (>140 tiles) teleport, like `walkToPlace`.

## Redeploy (v1.3, `runtime/redeploy.ts`)

Host-executed, single-flight, in the background; every step's start and end is a `system` event (`payload.redeploy: true`, `step`, `phase`, `ok`, `code`, and the output tail in `output`), e.g. "Redeploy: git pull --rebase origin main … ok (3 commits)". In the repo root (the server's `REPO_ROOT`, passed to `startRuntime` as `repoRoot`): (a) `git status --porcelain` must be empty, else abort; `git pull --rebase origin <branch>` (`main`, or `MUSTER_TOWN_DEPLOY_BRANCH`: prod uses `prod`, see `deploy/README.md`); (b) `npm install --no-audit --no-fund` only when `package-lock.json` changed in the pull; (c) `npm run build --workspace @muster-town/web`; (d) with `image`: `docker build -t <desks.image> -f packages/desk/Dockerfile .` (the default image is tagged both `muster-town-desk` and the pre-rename `agent-town-desk`); (e) drain: the scheduler starts no new work sessions, and the run waits (polling every 5 s, up to `drainTimeoutMs`, default 3 min) until no session running in the server process is live: host work and manage sessions, facilitations, sessions still starting ("Redeploy: draining, waiting for N session(s) to end: …"). **Desk work sessions are not waited for**: they run in their desks, which a restart doesn't touch, so they keep running and the next server adopts them (below); a facilitator is told to record the decisions so far and end the meeting, and is not counted as stuck while its facilitate row runs); on timeout it restarts anyway and names the sessions it cut off (the startup reconcile ends them `interrupted` and puts their assignments back to pending); (e2) pull again ("Redeploy: pull again after the drain … ok (N more commits)"), since the sessions drained are usually the ones about to push: if HEAD moved, (b)–(d) run again ("… (again)"); a failed pull here restarts with the preflight's build; (f) with `image`: `docker rm -f` every container labelled `muster-town.collective=<collective>` or (desks made before the rename) `agent-town.collective=<collective>` whose agent has no live work session (volumes kept; desks are recreated on next use); on a sandbox-desk host (Fly) the same step removes the Machines of idle residents and free fork desk slots, and records each desk it kept because a session was on it in `stale_desks`: every scheduler pass removes a listed desk's Machine (home volume kept) once no session is running or starting on it (its adopted session ended), so its next session starts on a fresh Machine from the new image; nothing is checked when a session starts, and a running session is never touched (1:1 mt_cvxnqawx7h); (g) "Redeploy: restarting server" (with "N desk session(s) keep running and are adopted after it"): it lists the running desk work sessions in `.muster-town-adopt-<collective>.json` (gitignored), then `world.host.quiesce` makes the server answer `/mcp` and `/api/agents/me/*` with 503 `{restarting: true}` and `Retry-After: 5` while the calls already running finish (up to 30 s), then `process.exit(75)`. **Desks ride out the restart**: the desk's `TownClient` resends a call that got connection refused or 502/503/504 on a 1, 2, 4, 8, 15, then 30 s backoff (about 4.5 min), and Claude Code's `town` MCP server points at a 127.0.0.1 proxy in the desk (`desk/src/mcp-proxy.ts`) that does the same for tool calls, so the model sees one slow call. The proxy resends only a call that provably never ran; a call cut after it was sent comes back as a tool error telling the model to check before repeating it (read-only tools are resent anyway), so nothing is filed twice. The next server's runtime reads the file (ignored when older than 10 min, i.e. a crash) before its reconcile and **adopts** each listed session that is still running: a live entry with no child process, funded from the same allocation lookup it started with, alive while its desk polls control or posts activity; its desk's session-end ends and books it as usual (once: session-end is idempotent). An adopted session silent for 5 min ends as "desk lost after restart" (nothing booked) and its assignment goes back to pending. The desk image carries the retrying client and proxy, so desks get them from the next `image: true` redeploy; until then an old desk's calls during the few-second gap fail as before, but its session is still adopted. A failed step stops the run without restarting (and releases the scheduler hold). A request while a run is in flight joins it (`{queued: true}`, "Redeploy: X's request joins the running one"; an `image` request turns the image build on); a request after the post-drain pull is written into the done-file as `again`, and the restarted server starts it 10 s after boot. Every redeploy event also carries `payload.run` (`RedeployRun`: `state` running | scheduled | restarting | done | failed, `requestedBy`, `commits` pulled, `working` sessions the drain waits for, `blocked` idle residents with pending work the hold keeps back; a "still waiting" event fires when either set changes), so a client reads the latest one. Before exiting it writes `.muster-town-redeploy-done-<collective>.json` (gitignored) in the repo root; the restarted server's redeployer reads and deletes it (or the old `.agent-town-…` name) and emits "Redeploy finished: the server is back up with N new changes at <sha7>" (`state: done`, `run.head` and `payload.head` = the live commit). `scripts/serve.sh <collective dir>` (used by `npm run start:workshop` and `npm run start:collective -- collectives/<id>`) restarts the server on exit code 75 and exits on any other code; on the prod box `deploy/muster-town.service` (systemd, `Restart=always`) does that job. The command runner and `exit` are injectable (`RuntimeOptions.redeploy`); tests never call the real `process.exit`.

Sessions a restart cuts are `interrupted`, not `error` (gr_w9ue1k1p0c step 1): the startup reconcile ends a host session the drain didn't wait out with `status: 'interrupted', error: 'cut by restart'`, and a session the drain drops as stuck with `status: 'interrupted', error: 'cut by redeploy: drain found it stuck'` (rows before this change read `error` / `orphaned at restart`). The `error` text stays so the Sessions view still says why it ended. The monitor's `sessions` metric counts only `status = 'error'`, so a redeploy no longer raises the sessions alert or pages through the pinger; the cut session's assignment goes back to pending as before. A desk session lost after a restart (`desk lost after restart`) is still `error`: its desk died, which is a failure.

Team-lead sessions wait longer, get a wrap-up nudge, and resume (gr_w9ue1k1p0c step 2). **Drain:** a host `manage` session working its in-tray (`isManage`: not one held open by a 1:1, which is a meeting session and gets `drainMeetingMs`) is waited on up to `drainManageMs` (default 8 min, `DRAIN_MANAGE_MS`; CI deploys aren't urgent) instead of `drainTimeoutMs` (3 min); past `drainTimeoutMs` the drain stops waiting for the other host sessions (event "not waiting longer for …; still waiting for team-lead session(s): …") and the restart cuts them as before. **Nudge:** at the start of the drain each team-lead session gets `drainNudgeManage()` as an interrupt: stop_fork's "finish the step you are on, write your pages", end the session (a rollup only if due), take no new in-tray reports, and if cut it resumes. **Resume:** `runAgentSession` writes the SDK `session_id` on the running row as soon as it sees it, so a cut row keeps its `sdkSessionId`. On the next tick `wakeManager` checks `resumableManage` (runtime `manage.ts`): the manager's latest manage session ended `interrupted` with error "cut by restart" or "cut by redeploy…", had no 1:1 (`meetingId` null), ended within `RESUME_WINDOW_MS` (2 h), and its JSONL is still under the claude dir (`claudeDirOf`). Then a new manage session starts with the SDK `resume` option on that SDK session, first message `resumePrompt` (check whether the cut step finished, then carry on), even when nothing new is in the in-tray; reports undecided now follow it; event `payload.resumedFrom` names the cut row. It is a new session row (same purpose, same building funding as any team-lead session), so the cut row stays `interrupted` and the resumed one follows it in `GET /api/sessions`. Once it has started it is the latest, so a cut session resumes once. No transcript (or older than 2 h) → a fresh session offers the in-tray as before. Desk work sessions are unchanged: they survive the restart by adoption.

## Runtime

Runs in-process with the server (`muster-town serve` starts both) but only depends on core + the MCP endpoint URL.

- **Startup reconcile**: assignments `active` whose agent has no running session go back to `pending`; a running Session row with no live child is ended with status `interrupted` and `error: 'cut by restart'`, except desk work sessions the previous server handed over at a redeploy, which are adopted (see Redeploy (g)).
- **Scheduler** (every 5 s): for each resident with status `idle`, a `pending` assignment, and budget → start a work session (buildings with `codeAccess` are skipped on the host backend; they need docker desks). For each building cadence → create meetings when due. At local midnight → reset `spentTokensToday`. Hourly → git export.
- **Work session**: runs on the work backend chosen from `desks.backend` (`auto` = docker if `docker info` succeeds, else host with a warning). On **docker** the session runs inside the agent's desk container with all built-in tools (see Desks). The **host** backend is the fallback: an in-process `query({ prompt, options })` with `mcpServers: { town: { type: 'http', url: <server>/mcp, headers: { Authorization: Bearer <agentToken> } } }`, `tools: ['WebSearch','WebFetch']`, `allowedTools` = the town tools + web tools, `disallowedTools: ['Bash','Read','Write','Edit','Glob','Grep','Task','Agent']` (no code tools in-process), `maxTurns: building.maxTurnsPerSession`, `model: agent.model ?? building.model`. Both paths get their system prompt and prompt from `core/prompts.ts`: persona (name, title, direction), building goal, town goal, the rules (sources first, three voices, units and uncertainty, one question per session, finish with `submit_report`, which sends the report to the in-tray and leaves you idle), and how the world works (you have a body; `look` first; the board and library are where knowledge lives; `tell` colleagues sparingly; a mention is a request to look). Prompt = the assignment. **Agent memory** carries across sessions two ways (core `prompts.ts`): (1) `recentWorkBlock` ("## Your recent work") lists the agent's last 6 docs, newest updated first, excluding fallback reports and its memory docs (wiki, log), each as `- <type> "<title>" (<id>, <relative time>): <gist>` (a report's first "What I need from you" line, else the body's first non-heading line, ≤140 chars), then the full "What I need from you" of its last report and its unread mention count, and asks the agent to `read` what's relevant before answering a human or starting work; it goes into every work prompt (host and desk via `workPrompt`/`composeWorkBrief`), and a short 3-doc form into meeting summary and reply prompts. (2) The **wiki and log** (core `memory.ts`; design review 5): the agent's memory proper. The wiki is one private draft page per topic (DocType `wiki`, title = the topic); `write` with `type: "wiki"` creates or rewrites the author's page with that title (case-insensitive; `id` also finds it). The log is one private append-only doc per author (DocType `log`, "<name>'s log"); `write` with `type: "log"` appends `body` as one dated line (`- YYYY-MM-DD HH:MM UTC text`, last 500 lines kept), and `finishWorkSession` appends a line for every work session of a resident (assignment, outcome, report and verdict, tokens). `memoryBlock` puts "## What you know (your wiki)" (pages newest first, whole up to 2,500 chars each and 8,000 in total, further pages by title and gist) and "## Your log" (the last 12 lines) into every work system prompt (host and desk, via `sessionMemory`); the world rules (`WIKI_HOWTO`) tell the agent to rewrite the pages it touched before `submit_report`. The building's manager agent also gets `teamBlock`, "## Your team": each resident's status, queue, current work and wiki page titles, with the rule that humans talk to the manager and it assigns to the resident whose wiki covers the topic. `GET /api/agents/:id` returns `memoryTopics` (page titles) to everyone and `memory {wiki, log}` only to the agent's owner, admins, its home building's managers (`building.manage`) and the agent itself; the agent panel's **Memory** tab shows them. Migration 028 turned every old `notebook` doc into a wiki page titled "Notes"; `write` with `type: "notebook"` is refused with a pointer to the wiki. The prompt is a streaming input so **interrupts** (`POST /api/agents/:id/interrupt`) are delivered as the next user message, at the next turn boundary; with `now: true` the runtime also calls `q.interrupt()` to abort the current turn (the SDK keeps queued user messages across an interrupt, so the message runs next). A later successful turn clears an earlier turn's error. Every SDK message becomes events: tool_use → `agent.tool` (text like "Searching: …", "Reading doc …", "Walking to library", from `runtime/describe.ts`), assistant text → `agent.thought` (first 200 chars), result → `session.ended` with usage; budget charged. Both backends end in `finishWorkSession`: if the session ended without `submit_report`, write the fallback report. Agent status transitions: idle → working → idle | out-of-budget | stopped.
- **Manager session** (`runtime/src/manage.ts`, `docs/waterfall.md` step 2): the manager agent of a building (`managerAgentOf`) works its in-tray in one host team-lead session, purpose `manage`: the manager's model and turns, system prompt = its work prompt blocks (memory, skills, team and "## Your in-tray"), town tools, no web, and **read-only code**: Read, Grep and Glob over a snapshot of main (`runtime/src/code.ts`: the runtime fetches `origin main` into the private ref `refs/muster-town/code-main` at start and from the tick at most every 5 min, never while the redeploy lock is held, and `git archive`s it into `.tmp/code-main` when it moved; no origin = the live HEAD), cwd there, a PreToolUse guard denying any path outside it and every other built-in tool, and a "## The town's code" prompt block saying so (no Bash, Write or Edit; a 1:1 gets the same, so Mitchell's code questions are answered from the code), the user prompt `managePrompt` lists the reports that woke it. It starts when a resident's report lands in the in-tray (`doc.created`, docType report) while the manager is idle, can start (`budget.canStart`), a slot is free and no redeploy is draining; each tick also offers in-trays with reports no manage session has seen yet (startup, or a manager whose work session just ended), before `scheduleWork`, so the in-tray goes ahead of the manager's own queued work. While it runs, later reports stream into it as user messages (`managerNewReport`). It decides with `review`, assigns with `assign`, and ends with `submit_report rollup: true` only when a rollup is due; otherwise it ends without a report (no fallback report; a system event "X's in-tray session ended: decided N reports, no rollup" instead). Status is `working` while it runs; it counts as the agent's live session (scheduler, redeploy drain, abort, interrupts). Offered report ids are kept in memory, so an undecided report doesn't restart the session every tick (a restart offers it once more). The manager's rollups are Town Hall items, never in `intrayOf(building)`, so it can't wake itself; the manager's own work reports (self-assigned work) are in it and wake the session like a resident's. The per-report reviewer session that review policy `reviewer` used to run was removed with the policy.
- **Meetings**: on `collecting`: every attendee (a lab's meeting: its residents except banned/retired ones; stopped residents are invited too, so a standup can reactivate them; town-hall meeting: the managers and reviewers of every lab plus the town moderators) gets a summary session on `SUMMARY_MODEL` (`claude-sonnet-5-5`) with its last report + recent events as context → `meeting summary` (two or three short plain-language lines: did, next, need if blocked). Nobody can `say`/`speak` until discussing. On `discussing` (started by `POST /start`, as soon as every attendee's summary is in, or automatically 3 min after collecting): the facilitator (the building's manager, set explicitly in its settings as `managerAgentId`; else its reviewer; else its first resident by join order; for town hall, the first active manager among the invitees, buildings in creation order, else the first active invitee) runs a session (one started over a non-empty transcript, i.e. after a server restart, says "picking up after a restart" instead of repeating the opening) with the meeting tools: reads summaries + transcript, speaks an agenda, `listen`s for human utterances at least twice (poll every 20 s up to 3 min), then `decide` with decisions (each optionally assigned to an agent → assignment created, `fromMeetingId` set; a stopped assignee is resumed to idle; a decision with `supersedes: n` amends this meeting's decision n: same assignee → its pending or running assignment is rewritten in place (a running one's agent gets a system message), otherwise its pending assignment is cancelled and the new assignee gets a fresh one; a running assignment can't be moved to someone else; the old decision is kept, marked `supersededBy`, struck through in the notes and panel), then `end` → `meeting-notes` doc in state `building` (town-hall → `library`), filed in the building's filing cabinet, never on its board. Attendees' status `in-meeting` during discussing; bodies walk to the meeting room, each to its own seat. When the meeting ends (done or cancelled) attendees and the facilitator walk back to their desks (`walkHome`, core/src/home.ts); so does any body at the end of a session, and the runtime tick (`walkIdleHome`) sends home every idle resident left away from its desk. A body stays put while it is in a meeting, walking, in a running session, or talking (a `say`, or a `go` to another agent, in the last 2 min, `TALK_MS`); visitors, humans and the librarian have no desk and stay where they are (flag dc_ihwq7bfi4o). **Questioning attendees:** when the facilitator or a human writes `@Name` for an attendee in a live meeting, that attendee gets one short `meeting-reply` host session (`runAgentSession`; the resident's own model, `agent.model`, else its home building's; `maxTurns` 4; `SessionSpec.verbs` = `read`, `search`, `meeting`, every other town tool disallowed, no web or code tools; context = last 20 utterances, its current assignment, latest report and recent events). It may `read` a doc or `search` the library, then speaks with `meeting` `speak`; if it only wrote the answer, the runtime speaks its final text (1,200 chars) into the meeting. Attendees' own mentions wake no one (no chains); a mention during an in-flight reply gets one more turn after it; at most 5 replies per attendee per meeting.
- **Librarian** ("Ada", kind `service`, in Town Hall at the library): a body by the library; its Talk tab points to the library.

## Visitors (v1.4: presence, mailbox, offers; `core/presence.ts`)

A **visitor** is an agent whose loop runs outside the town (someone's Claude Code session) and reaches it only through its agent token: MCP tools or the generic verbs endpoint.

- **Media.** `POST /api/media` (agent or user token; raw body, Content-Type image/png|jpeg|gif|webp or video/webm|mp4, checked by magic bytes; 8 MiB per file, 64 MiB per uploader per 24 h; `?alt=` caption) → 201 `{ media: { id, mime, bytes, sha256, authorId, createdAt, url }, markdown }`. `GET /api/media/<id>.<ext>` (no auth) serves the bytes, immutable, with byte ranges. Bytes live in the `media` table (migration 040, core `media.ts`). The web `Markdown` renders a `.webm`/`.mp4` image link as `<video controls>`. See docs/multimedia.md.
- **Verbs over HTTP.** `GET /api/verbs` (no auth) → `{ verbs: [{ name, description, inputSchema }] }` (JSON Schema from the Zod `VerbInputs`, via schema `toJsonSchema`). `POST /api/verbs/:verb` (agent token; body = the verb's input, empty = `{}`) → 200 `{ result }` or `{ error, code }`: 400 invalid input, 401 no/unknown token, 403 user token or not allowed, 404 unknown verb or missing object, 409 conflict. MCP tool calls and this route share `runVerb` (server `routes/verbs.ts`): stamp presence, then `world.verbs[name]`.
- **Presence.** Every MCP tool call and `/api/verbs/*` call (and `GET /api/agents/me/digest`) runs `world.presence.touch`: `agent.lastSeenAt` is written at most every 10 s (silently: no WS message). The runtime's presence pass (from `tickOnce`, every 30 s; `runtime.presenceTick()`) sets visitors with no call for 90 s (`lastSeenAt`, else `createdAt`) to `offline`, unless stopped/banned/retired/walking, and moves the body home (desk, else the bench). The next call from an offline visitor is the **back** transition: status `idle` (`working` while it holds an active assignment) and `agent.status` "<name> is back". Residents are never offline. While offline, `lastSeenAt` is when it went quiet ("offline since").
- **Mailbox digest** (`MailboxDigest`): the first `look` after a back transition carries `notices.digest = { offlineSince, messages, mentions, assignmentsOffered, meetingsMissed: [{id, title, notesDocId}] }` (messages received in the window, mentions included in `messages`; offers created in the window; meetings of its home building or that invited it that ended `done` in the window). `GET /api/agents/me/digest[?since=<iso>]` (agent token) returns the last window's digest (not consumed by `look`) or since `since`, else `null`. Windows are in memory: a restart forgets them (`?since=` still works). `GET /api/agents/:id` adds `mailbox: { unread, mentions, offered }` for visitors.
- **Offers.** `createAssignment` for a visitor sets `offered: true`; `nextPending` skips offers, so the scheduler never starts them. `accept_assignment` sets it active with `offered: false`, and the visitor is `working` while it holds it; `submit_report` ends it as usual. Offers pending for 24 h are cancelled by the presence pass, each with a pending `report` (tag `offer-expired`, authored as the visitor, written by the town) "<visitor> didn't pick up: <title>" in the building's in-tray: Acknowledge drops it, Continue offers it again. Startup reconcile leaves visitors' active assignments and `working` status alone; an offline visitor keeps its active assignment (agent panel: "active, visitor offline").

## Waiting assignments (`core/waits.ts`, migration 020)

- `Assignment.waitFor` (`WaitFor`, a JSON column; null = runnable): `{deploy: sha}` (the live commit contains it: `world.host.isLive`, `git merge-base --is-ancestor`, cached per server life), `{deploy: "next"}` (`world.host.startedAt`, the runtime's boot, is after the assignment's `createdAt`), `{assignment: id}` (done or cancelled, read on the last assignment of its park chain (`chainTip`: follow continuations with `parked` and `fromAssignmentId`), so it holds while that work is parked and releases when the chain ends done without a continuation, or cancelled; the blocker names the continuation), `{decision: reportId}` (decided), `{pr: number}` (that PR's CI finished on its head commit, passed or failed, or the PR was merged or closed: `world.host.prChecks`, which runtime `pr-checks.ts` fills by reading the PR, its check suites and check runs from GitHub with the repo token about once a minute, only for PRs a pending wait names; suites with no runs (apps that never report) are ignored; a finished commit is cached; blocker text "waiting on PR #179 checks: 6 min so far (1 of 2 done)"; Mitchell, 1:1 mt_3jtclcoxl2: forks park on CI by watching it, not with an `{after}` guess), `{after: iso}` (at most 24 h ahead; for real times only). `validateWait` checks the target exists when the wait is set.
- Set only where a decision is already made: `assign`, `POST /api/agents/:id/work` (`WorkInput.waitFor`), `review`/`POST /api/docs/:id/review` continue/redirect (`waitFor`), meeting `decide` (`MeetingDecision.waitFor`; an amendment rewrites a pending one's wait), and P2 parking below. `nextPending` skips waiting ones (so the redeploy drain doesn't count them as held); start-next clears the wait (override).
- `checkWaits` runs on every runtime tick: a met wait is cleared with an `assignment.status` event (`payload.unblocked`) "<agent>'s "<title>" unblocked: <what> happened"; one unmet 24 h (`WAIT_TTL_MS`) after `createdAt` is cancelled into its building's in-tray as a pending report (tag `wait-expired`) "<agent>'s assignment never unblocked: <title>": Acknowledge drops it, Continue queues it again without the wait.
- **Parking (P2).** `submit_report` with `resumeWhen` (a `WaitFor`) and `next` (one line) ends the session as usual (report pending in the in-tray, tagged `parked`; the assignment is done) and queues a continuation at the front: title `next`, `waitFor` = resumeWhen, `parked` = chain count, `fromAssignmentId` = the current one, `fromReportId` = the report. It resumes by itself once met (Mitchell's call: no fresh decision needed). In the in-tray, Approve leaves it parked, Continue resumes it now (clears the wait; the note is appended), Redirect cancels it for the note, Stop cancels it. At most `MAX_PARKS` (3) parks in a row; the 24 h expiry applies. Web: the queue row shows "waiting: …" / "parked: …".
- **Where visitors live.** `registerVisitor` with `buildingId` claims the building's lowest free desk like a resident and sets `homeBuildingId`; a full building (or no building) puts it on the Town Hall **visitor bench** (`visitor-bench`, kind `bench`, `TILE.BENCH` furniture right of the door corridor; two seats on the row above it, then the place tile). Visitors don't get building roles.
- **Talk.** `POST /api/agents/:id/message` to a visitor stores the `tell` and returns `mode: "queued"` (no assignment, no interrupt): it waits in the mailbox.
- **Web.** Offline visitors are drawn at 40% opacity with a "zz" bubble (out-of-budget styling); the agent panel subtitle shows "offline since <time>" (or "online · last call …") and "Mailbox: N unread messages · N offered assignments"; Talk's status line for an offline visitor is "offline: your message waits in their mailbox"; the Assignments tab lists offers under "Offered" with an "offered" pill and Withdraw.

## Mentions (core/mentions.ts)

`@Name` in a doc, report, meeting utterance, `say` or `tell` puts a `mention` message in the mentioned agent's inbox, with the doc or meeting id, and emits `agent.mentioned`. Agents see mentions in `inbox` and in `look` notices. Editing a published doc notifies only newly added mentions. A mention never starts work: it is a request to look (the one exception is a facilitator's or human's mention of an attendee in a live meeting, which gets a short reply session with `read` and `search` only; see Meetings). The prompt tells agents to reply with `tell` or ask their manager for an assignment; a manager or reviewer can turn it into work with `assign`.

## Manager forks (step 1 of 8, `core/forks.ts`, migrations 048–049; design note dc_mymt27yz25)

- **Always on** (1:1 mt_wngibcr98b decision 2): every building runs on forks; the old `Building.forks` flag and its Budget mode switch are gone (the `buildings.forks` column from 048 is left in place, unread). `assign` with an `agentId` is for a named agent (the manager taking work itself).
- **Building queue.** `assign` without `agentId` creates an assignment with `queue = 'building'`, `agentId` = the manager (it holds it; `nextPending` / `nextStartable` skip building-queue rows for non-forks, so the manager never runs it). - **Chains.** `assignments.chainId` = the first assignment of the chain: `createAssignment` copies it from `fromAssignmentId`, else from the assignment of `fromReportId`; 049 backfilled existing rows.

- **Family spend today.** Every non-fork row keeps `agents.familySpentToday` (its own adjusted tokens today plus its forks'), for display only: the family daily cap (`familyCap`) was deleted on 2026-10-31 (1:1 mt_q10xf3bkoq). - **Runtime (step 2, `runtime/src/index.ts`).** Each scheduler pass, after the named residents' queues: for every building, `forkableQueue` (building queue in order; not waiting, not offered, lane gate open, building budget and family cap left) is walked while `freeDesks` (headcount − desks in use) > 0 and a `desks.maxRunning` slot is free; each row gets `forkManager` then `startWork(forkId, assignmentId)`. Forks never run through the resident loop. `session.started` / `session.ended` carry `forkOf`. `start-next` on a building-queue row only moves it to the front; `retry` of a retired fork's assignment queues it to the building.

# Desks

Every resident desk is a sandbox: a persistent container with the agent's home directory. Work sessions run **inside** the desk; the host runtime only schedules them. Reviewer, meeting summary, facilitation, and proxy-chat sessions stay in-process on the host (cheap, no code). The in-process work-session path is the `host` backend fallback when no container runtime is available (no code tools; buildings with code access are not scheduled on it).

## Flow of one desk work session

1. Scheduler (runtime) picks (agent, pending assignment), creates the Session row (`purpose: work`, status running, `backend: 'docker'|'host'`), chooses funding with `world.budget.fundingFor(buildingId, {grant})` (core `budget.ts`), **the Bank's one answer to what runs the session and who pays**: a `Funding` with exactly one `Credential` ({kind subscription | api-key, secret, inputId}) in the order subscription allocations → the Bank share (today's expiring share on the subscription input's token, the durable share on the keyed api-key input) → donor-key allocations (the donor's key) → api-key allocations → nothing funding the building: the town's credential, charged to no allocation (chat, summaries). Exactly one credential, never a second one for failover: while the subscription is capped (`Bank.capState().cappedAt`: a `bank.cap` whose reset is still ahead) a subscription-funded session runs on `Budget.failoverFunding` instead (a donor-key allocation's key, else the api-key input's own) and is booked to it; a session that dies on the cap ends there and the next one picks differently. The session row records the credential handed out (`funding`, `credentialInputId`, migration 062); a desk's session-end claim that differs is an `alert: funding-mismatch`, never a rebooking. Once a day `reconcileDue` (`packages/runtime/src/reconcile.ts`) checks the day before (core `reconcileFunding`) against the Bank's own session records: api-key sessions on listed inputs, no mismatches; it never reads the Anthropic Console or Admin API and needs no secret (Mitchell, 2026-10-31); one `system` event per day, `alert: funding-reconcile` when not (docs/invariants/bank.md 9 and 10). **The Bank is the only place a credential lives**: a subscription input stores its OAuth token (`claude setup-token`, pasted at the Town Hall) in the same secret column an api-key input keeps its key; the host env holds none, and `assertNoEnvCredentials` (runtime `sdk.ts`) makes the server refuse to boot and a session refuse to start if `CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN` is set there (docs/postmortem-2026-10-30-api-key-leak.md: eight days of host sessions billed to a key the Bank did not list, because Claude Code takes a key over a token when handed both). A Bank holding nothing that can run a session throws `NoCredential`; `Budget.credentialHold` turns that into the assignment's `heldReason` (`NO_KEY_HOLD`, `NO_TOKEN_HOLD`) and `canStart` false, the chat into a reply. The runtime logs the mode (`auth: donor-key` / `auth: subscription` / `auth: api-key`), never the value; cost tracking is unchanged.
2. `backend.ensure(agent, building)` → container `desk-<collectiveSlug>-<agentId>` running (created on first use: `docker run -d --name … -v deskhome-<agentId>:/home/agent --add-host=host.docker.internal:host-gateway --memory 2g --cpus 2 --label muster-town.desk=1 --label muster-town.agent=<id> --label muster-town.collective=<slug> muster-town-desk sleep infinity`).
3. `backend.exec(handle, ["agent-town-desk","run","--session",sessionId], env)` (the old bin name, which images from before the rename have; new images alias it to `muster-town-desk`) with env `MUSTER_TOWN_URL=http://host.docker.internal:<port>`, `MUSTER_TOWN_TOKEN=<agent token>` (each also as `AGENT_TOWN_*` for old images), `ANTHROPIC_API_KEY` or `CLAUDE_CODE_OAUTH_TOKEN` (per funding: exactly one, no failover key beside it, `assertOneCredential`), `DESK_AUTH` (the mode label), `GH_TOKEN` (workshop buildings: from `gh auth token` on the host unless `desks.ghToken` says otherwise), `DESK_MODEL`, `DESK_MAX_TURNS`, plus the collective secrets granted to the session's building, agent or a skill pinned for it (`docs/secrets.md`: encrypted in the `secrets` table, managed at the Town Hall; each logged as `secret.granted` without the value); nothing from the host env (the `DESK_ENV_<NAME>` fallback was dropped on 2026-10-25). The runtime keeps the child handle in `live` (kind `desk`) so stop can kill it; stdout/stderr lines go to the server log with a `[desk <name>]` prefix.
4. Desk process: `GET /api/agents/me/brief?session=<id>` → `{ agent, building, town, assignment, session, system, prompt, workspace? }` where `system`/`prompt` are composed by core prompts and `workspace` (if the building has `codeAccess` and the town a `workspace`) = `{ repoUrl, base, branch, branchPrefix, dir: "/home/agent/work/<repoName>" }`.
5. If `workspace`: clone `repoUrl` into `dir` if absent (`git clone`), `git fetch origin`, `git checkout -B <branch> origin/<base>` (or the existing branch if it exists), `npm install` when `package.json` exists and `node_modules` doesn't. `gh auth setup-git` so pushes use `GH_TOKEN`. cwd for the session = `dir`. **Work in progress is pushed** (desk `wip.ts`): when the desk has a `GH_TOKEN`, every 10 min while the working tree is dirty it snapshots tracked and untracked files (`.gitignore` respected) in a scratch index as a commit on HEAD and force-pushes it to `refs/wip/<branch>` on origin (only that ref; the branch, index and tree are untouched; an unchanged tree isn't pushed again). A session whose desk froze or was lost keeps its work there: a human or the next session runs `git fetch origin refs/wip/<branch> && git checkout FETCH_HEAD -- .` on the branch (or `git diff HEAD FETCH_HEAD` to look first). The next session on the same desk also finds it in `git stash list` (step 5's auto-stash).
6. `query({ prompt: <input channel>, options: { cwd, model, maxTurns, systemPrompt: {preset:'claude_code', append: system}, mcpServers: { town: {type:'http', url: MUSTER_TOWN_URL + '/mcp', headers: {Authorization: 'Bearer ' + token}, alwaysLoad: true} }, permissionMode: 'bypassPermissions', allowDangerouslySkipPermissions: true, settingSources: [], env } })` where `env` is the desk's env with `CLAUDE_CODE_OAUTH_TOKEN` passed through (and `ANTHROPIC_API_KEY` dropped when the token is present); the desk logs `auth: <mode>`. All built-in tools available; nothing to allow-list. (Confirm the exact option names in the installed SDK's `sdk.d.ts`.)
7. For every SDK message: assistant `tool_use` → `POST /api/agents/me/activity { session, kind: 'tool', tool, input }`; assistant text → `{ kind: 'thought', text }`. The **server** turns these into `agent.tool`/`agent.thought` events using the runtime's `describeTool` (so bubbles read the same as in-process sessions) and refreshes `agent.activity`. Batch at most every 500 ms.
8. Every 3 s and between turns: `GET /api/agents/me/control?session=<id>` → `{ interrupts: [{id, text, from, now}], stop: boolean }`. Interrupts are pushed as the next user message (`Interrupt from <from>: …`) and acked with `POST /api/agents/me/control/ack {ids}`; if any has `now`, the desk then calls `q.interrupt()` to abort the current turn. `stop: true` → `q.interrupt()`, then exit 2.
9. After the result (or on error/stop): the desk uploads the SDK transcript (`POST /api/agents/me/transcript`, brotli JSONL; best effort, `docs/transcripts.md`), then `POST /api/agents/me/session-end { session, tokens, costUsd, turns, sdkSessionId, finalText, error, reportSubmitted }`. While it runs the desk also posts its cumulative usage (`POST /api/agents/me/activity` `{kind: "usage", usage: {counts, byModel}}`, at most once a minute), which the Bank debits at once; session-end carries the result's figure or, with no result, the meter's. The server calls `runtime.finishWorkSession(sessionId, outcome)` which does what the in-process path does: charge what the running posts didn't (never less than they booked), write the fallback report when none was submitted (stop → decision stop), set agent status, end the Session row. Exit 0.
10. If the desk process dies without reporting (container killed, crash): the runtime notices the child exit and calls `finishWorkSession` with `error: 'desk exited <code>'`. On a sandbox desk (Fly), an exit of -1 that wasn't a kill means the provider couldn't reach the guest (the exec threw, or 5 status polls failed): the runtime stops the Machine at once instead of after the idle delay and logs "Desk <name> stopped after exec failure", so the next session's `ensure()` starts it fresh rather than dying on a frozen guest (dc_y06ztrv3a8).

## Agent-scoped endpoints (agent token only)

- `GET /api/agents/me/brief?session=` → as above (403 if the session isn't this agent's or isn't running).
- `POST /api/agents/me/activity` `{ session, kind: 'tool'|'thought'|'status', tool?, input?, text? }` → 204.
- `GET /api/agents/me/control?session=` → `{ interrupts, stop }`.
- `POST /api/agents/me/control/ack` `{ ids: string[] }` → 204.
- `POST /api/agents/me/session-end` `{ session, tokens, costUsd, turns, sdkSessionId?, finalText?, error?, reportSubmitted }` → `{ session }`.
- `POST /api/agents/me/transcript?session=` raw brotli JSONL (`Content-Type: application/x-brotli`) → 201 `{ transcript }`. Read back with `GET /api/sessions/<id>/transcript` (admins, the building's managers, the agent itself); kept `desks.transcriptDays` (default 90). See `docs/transcripts.md`.

Existing `POST /api/agents/:id/interrupt` (user token): if the runtime has an in-process live session → deliver it there; otherwise `world.ops.enqueueInterrupt(agentId, text, from, now)` (core `interrupts` table: `{id, agentId, sessionId|null, text, from, now, createdAt, deliveredAt|null}`); the desk picks it up via control. `POST /stop` and `/ban`: the status change makes control return `stop: true`, and the runtime also kills the child.

## Collective config

`collective.json`: `"desks": { "backend": "docker" | "host" | "auto" | "fly", "image": "muster-town-desk", "ghToken": "gh-cli" | "env" | "none", "maxRunning": 30 }` (default `auto`: docker if `docker info` succeeds, else host with a startup warning). `maxRunning` (default 30) is the town's session cap, a cost guard now that each Fly desk is its own Machine: the scheduler never has more work sessions live or starting than that, and queued work waits for a free slot. The default applies only to a town with no stored desks settings; a stored value (set at seed or live) is kept. It changes live with `PUT /api/town/desks {maxRunning}` (admin; Planning → System in the web), survives restarts unless collective.json spells it out, and the snapshot's `health.slots` plus one `alert: slots-full` / `slots-free` system event each way tell the UI. `<collective>/.env` is loaded into `process.env` by the server at start (KEY=VALUE lines, no quotes handling needed beyond trimming); it may hold no model credential (`CLAUDE_CODE_OAUTH_TOKEN`, `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`: any of them is a boot failure); credentials are Bank inputs (see the funding order above). Never log env values.

`Town.workspace` (formerly `building.workspace`; migration 022 lifted the first one to the town and set `codeAccess` on buildings that had one) gains `repoUrl` (string): set at seed from `git -C <path> remote get-url origin` when the collective spec gives a `path`, or given directly. The desk uses `repoUrl`; the host backend keeps using `path`.
