# Invariants: asks

What must always hold for asks (`packages/core/src/asks.ts`, the `asks` table from migration 097). An ask is something only a human can do, stored and typed instead of parsed out of a report's prose. Each invariant names the test that proves it. The design is in [docs/legible-delegation.md](../legible-delegation.md) §3-4 (build steps 1-2 in §11), and the map is in [docs/architecture.md](../architecture.md#map-the-system-in-10-minutes).

**Citation format** (checked by `npm run check:docs`, see `scripts/check-doc-refs.ts`): each invariant has one or more lines like

- Test: `packages/core/test/asks.test.ts` › `only a human who can fund decides an ask; a deferred ask stays listed until decided`

The first code span is the test file. The second is the `it` text, copied exactly. If the file is missing or the text isn't in it, the check fails, so renaming a cited test means updating this doc in the same change.

## Invariants

1. **An ask is created in code where its source is created, never parsed later.** A grant proposal, a step report whose forecast projects past the ceiling, and a grant held at its checkpoint file a money ask on the grant (`Grants.event`, `fileForecast` and `Grants.checkpoints`; the last two fold into one, grants.md invariant 12); an asked retainer a money ask on its schedule (`askRetainer`); `request_human` a credential ask when it asks for a token or key, else a click (target the request); a captain ask and an access request a click. Each carries its type, target, building, record, title, body from the source's own words and the branches of its decision verbs.
   - Test: `packages/core/test/asks.test.ts` › `a proposal files one money ask; a second ask on its grant folds in as a source line; funding retires it with the event's text`
   - Test: `packages/core/test/asks.test.ts` › `a checkpoint, a retainer, an outbox request, a captain ask and an access request each file one ask, and the event that decides each retires it`
2. **One live ask per target.** A second ask on a target (targetKind + targetId) that already has an open or deferred one folds into it as a source line (`ask.folded`); no second ask is made, and the same record and line again changes nothing.
   - Test: `packages/core/test/asks.test.ts` › `a proposal files one money ask; a second ask on its grant folds in as a source line; funding retires it with the event's text`
3. **The event that decides a target retires its live asks, with that event's text as `retiredBy`.** The hooks sit next to the state change, never on a timer: a grant funded, continued, adjusted, countered, rejected, cut, closed, withdrawn or stopping (`Grants.event`); access let in or declined; a captain ask accepted or declined; a request claimed, declined, withdrawn or deleted (`requestAction`); a retainer decided or ended; a key result whose status a human sets, or that is met or missed by anyone; and a reset account's pending requests.
   - Test: `packages/core/test/asks.test.ts` › `a checkpoint, a retainer, an outbox request, a captain ask and an access request each file one ask, and the event that decides each retires it`
4. **Every call `overtakenReason` labels overtaken has had its asks retired by a hook.** The regex in `packages/core/src/secretary.ts` (kept from the retired digest card) only reads an untyped rollup's prose; the hooks are the mechanism.
   - Test: `packages/core/test/asks.test.ts` › `every case overtakenReason detects is also retired by a hook`
5. **Only a human decides an ask; nothing decides one by silence.** `decideAsk` needs a human who can fund the ask's building, and records who, when and what (the branch label, plus the human's optional note as "<label>. <note>", up to 2000 chars; the ask's building manager hears it in their inbox). An outbox request's ask decides through the request itself: Claim takes an optional note (kept as `requestNote`, sent to the agent author with the claim), Decline a required one (the server refuses a bare decline); `deferAsk` (a human or the Secretary) parks an open ask behind an event, and it stays listed in the Town Hall in-tray's `asks` (and counted in its badge) until decided or retired. When the ask or target id it waits behind is decided or retired, it is open again (`reopenDeferred`, `ask.reopened`). A decided ask is final.
   - Test: `packages/core/test/asks.test.ts` › `only a human who can fund decides an ask; a deferred ask stays listed until decided`
   - Test: `packages/core/test/asks.test.ts` › `a deferred ask opens again when the ask or the target it waits behind is decided or retired`
6. **A rollup's typed `asks` list covers what its prose asks.** `submit_report` with `rollup: true` and `asks` refuses (filing nothing) when an id its Needs section or a real "Your call" names is no ask's target, when it asks something in words with an empty list, when a money ask names no grant or retainer, or when a target does not exist. A money ask folds into its item's own ask; a rollup with no Shipped items whose every ask folded is acknowledged on submit. Without the list the prose is read as before and the rollup is tagged `untyped-asks` when it asks something.
   - Test: `packages/core/test/asks.test.ts` › `a rollup's typed asks: refused when a Needs or Your call id is not a target; a money ask folds into its grant's ask; without the list it is tagged and reads the prose`
7. **The boot backfill is idempotent.** `backfillAsks` (World construction) files the ask of every open proposal (not a countered one: it waits on its manager), held grant, asked retainer, open outbox request, pending captain and access request, and each pending rollup's live calls; a second run creates nothing.
   - Test: `packages/core/test/asks.test.ts` › `backfill files the asks of everything already open, a pending rollup's calls included, and a second run creates nothing`
8. **An author's ask card is refused only for missing structure; style rules are warnings** (Mitchell, 1:1 mt_ewxnhs90cq decision 5, 2026-11-10: "i don't think we need the linter for text"). An author's card, a rollup's typed `asks`, `propose_grant`'s card (the explorer's `ask`, else the one the town writes from the plan) or the Planner's `calibrate` card, is refused every time it lacks structure (`askStructure` in `packages/schema/src/ask.ts`, `refuseMissingStructure` in `packages/core/src/asks.ts`): two branches as buttons, the recommendation field, and its type's hard contract fields (money: prior decision, spent, steps; click: who is parked; credential: scope and fallback; meeting: the question; policy: the rule). There is no retry limit and no `ask.refused` event. Every other rule (sentence length, ids in the body, semicolons, parentheses, one instruction per sentence, condition first, ellipsis, dictionary words, and the soft contract fields: money claims, click permission, policy what-I-did and reversing cost) never refuses: `createAsk` files the card and records them as one `lint` history entry starting "warnings:", the author's answer names them, and no tag or pill marks the card. A card the town writes from a source's own words is filed the same way.
   - Test: `packages/core/test/ask-contract.test.ts` › `structure is the hard contract fields, two branch buttons and the recommendation field; the rest only warns`
   - Test: `packages/core/test/ask-contract.test.ts` › `an author's card missing structure is refused every time; style rules file it with warnings in its history`
9. **A claim's check result is never older than 5 minutes when shown.** `GET /api/asks/:id` re-runs an ask's mechanical claims (`pr`, `url`, `api`, and `kr` when its howToCheck is a curl or a URL) whose result is missing or older than `CLAIM_STALE_MS` before it answers (`runClaimChecks`, `packages/core/src/ask-checks.ts`); the server also runs them in the background when an ask is filed. A check that cannot run is stored as a failed result with its reason, never thrown.
   - Test: `packages/server/test/asks.test.ts` › `lists open asks, records what a signed-in human opens (never an agent), re-runs a stale claim check on open, and decides and defers`
   - Test: `packages/core/test/ask-checks.test.ts` › `runs pr, url, api and kr checks, leaves manual alone, stores the results and goes stale after 5 minutes`
10. **No ask title or body contains an ellipsis.** A card is written for the reader and never quotes the record (docs/legible-delegation.md §5): the town names a grant by its `title` (migration 105), never by its clipped objective, and the proposal card's second line is the first key result, dropped rather than clipped when it fails the linter. The linter's `no-ellipsis` rule refuses "…" in a title, body or recommendation, a manager's card too. At boot `retitleClippedAsks` rewrites every live town-written card that still carries one from its target, once, keeping its id, sources, rank and status; a card with no target card loses its ellipsis and keeps its words.
   - Test: `packages/core/test/grant-title.test.ts` › `the proposal card has no ellipsis, never quotes the objective, and its second line is the first key result`
   - Test: `packages/core/test/grant-title.test.ts` › `rewrites a live clipped town card once from its target, keeping its id, sources, rank and status; a card with no target card loses its ellipsis and keeps its words`
   - Test: `packages/core/test/grant-title.test.ts` › `refuses an ellipsis in an ask's title, body or recommendation`
11. **The Secretary's 1:1 carries the item open in the human's decision queue.** The queue PUTs the item on screen as the 1:1's `focus` (`PUT /api/meetings/:id/focus`, migration 106; only that 1:1's human, the same item twice writes nothing, null when the queue closes). Each of the human's lines reaches the agent with an "Open on <name>'s screen" block rebuilt from live data (`focusBlock`, `packages/core/src/meeting-focus.ts`): an ask decided or retired since it was opened says so, a gone id says gone. `act_in_1on1` with no target acts on that item, only on the human's cited words.
   - Test: `packages/core/test/meeting-focus.test.ts` › `listen carries the open item from live data: the ask's card, branches, status and target, then 'retired since it was opened'`
   - Test: `packages/core/test/meeting-focus.test.ts` › `act_in_1on1 with 'fund it' and no target decides the focused grant as the human`
   - Test: `packages/server/test/meeting-focus.test.ts` › `only the 1:1's human sets the open item; another human, an agent and a guest are refused; the same item twice is a no-op`
12. **An ask read from a rollup's prose is titled with its call's whole first sentence.** `asksFromRollupProse` titles it with `proseAskTitle` (packages/schema/src/grant-title.ts): markdown and parenthesised asides dropped, never cut at a colon ("A 1:1 with …", "Optional: give …" read on), and a sentence over 160 characters cut at its last clause boundary, never in its first third. At boot `retitleProseAsks` gives every live prose-read ask that title again from its source line, keeping its body, sources, rank and status (a "retitled" entry); a manager's typed ask is untouched, and the backfill files no twin of a retitled one.
   - Test: `packages/core/test/prose-ask-titles.test.ts` › `reads the three live examples whole: no cut at the colon of 1:1 or after Optional, no cut at 8 words`
   - Test: `packages/core/test/prose-ask-titles.test.ts` › `the repair retitles a live clipped prose ask from its source line, keeps body, rank, sources and status, leaves a manager's ask alone, and the backfill files no twin`
13. **A prose call is a money ask only when it asks for tokens.** `asksFromRollupProse` types each call by `proseAskShape` (packages/core/src/asks.ts): a money ask on the grant (else retainer) it names only when the call asks for tokens (fund, counter, reject, adjust, cut, continue, raise, top up, stop, close, approve, a ceiling, or a token figure such as "150k"); otherwise a policy ask (a rule veto) or a click with Done / Decline, on the request, captain, access request or key result it names, else untargeted. A call that merely mentions a grant never lands in that grant's row, where it would read as a funding question or become its gate. At boot `retypeProseAsks` retypes the live prose asks the older rule filed as money (a "retyped" entry), keeping id, title, body, sources, rank and status; a target already holding a live ask leaves it untargeted.
14. **One rollup line files one ask.** `asksFromRollupProse` counts a line as filed when any ask from that rollup carries its title or line, whatever its target or type now, so a boot whose backfill runs before `retypeProseAsks` files no twin (dca8e0e9 made two: ak_mpfdm8kjj5, ak_3nakbll1su). At boot `foldTwinProseAsks` folds live twins (same rollup, same title or line) into one: the one with a target, else a deferred one, else a ranked one, else the oldest; a twin deferred behind its own twin is never the one kept. A deferral behind a folded ask follows the fold: the ask it folded into (or one whose keeper is settled) opens again, any other waits behind the kept one (c4952482's boot kept four asks deferred behind the twin folded into them).
   - Test: `packages/core/test/prose-ask-titles.test.ts` › `at boot the backfill runs before the retype and still files no twin of a mis-typed line; the twins an older boot made fold into one`
