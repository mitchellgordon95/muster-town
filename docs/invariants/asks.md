# Invariants: asks

What must always hold for asks (`packages/core/src/asks.ts`, the `asks` table from migration 097). An ask is something only a human can do, stored and typed instead of parsed out of a report's prose. Each invariant names the test that proves it. The design is in [docs/legible-delegation.md](../legible-delegation.md) §3-4 (build steps 1-2 in §11), and the map is in [docs/architecture.md](../architecture.md#map-the-system-in-10-minutes).

**Citation format** (checked by `npm run check:docs`, see `scripts/check-doc-refs.ts`): each invariant has one or more lines like

- Test: `packages/core/test/asks.test.ts` › `only a human who can fund decides an ask; a deferred ask stays listed until decided`

The first code span is the test file. The second is the `it` text, copied exactly. If the file is missing or the text isn't in it, the check fails, so renaming a cited test means updating this doc in the same change.

## Invariants

1. **An ask is created in code where its source is created, never parsed later.** A grant proposal, a step report whose forecast projects past the ceiling, and a grant held at its checkpoint file a money ask on the grant (`Grants.event`, `fileForecast` and `Grants.checkpoints`; the last two fold into one, grants.md invariant 12); an asked retainer a money ask on its schedule (`askRetainer`); `request_human` a credential ask when it asks for a token or key, else a click (target the request); a captain ask and an access request a click. Each carries its type, target, building, record, title, body from the source's own words and the branches of its decision verbs.
   - Test: `packages/core/test/asks.test.ts` › `a proposal files one money ask; a second ask on its grant folds in as a source line; funding retires it with the event's text`
   - Test: `packages/core/test/asks.test.ts` › `a checkpoint, a retainer, an outbox request, a captain ask and an access request each file one ask, and the event that decides each retires it`
2. **One live ask per target.** A second ask on a target (targetKind + targetId) that already has an open or deferred one folds into it as a source line (`ask.folded`); no second ask is made, and the same record and line again changes nothing.
   - Test: `packages/core/test/asks.test.ts` › `a proposal files one money ask; a second ask on its grant folds in as a source line; funding retires it with the event's text`
3. **The event that decides a target retires its live asks, with that event's text as `retiredBy`.** The hooks sit next to the state change, never on a timer: a grant funded, continued, adjusted, countered, rejected, cut, closed, withdrawn or stopping (`Grants.event`); access let in or declined; a captain ask accepted or declined; a request claimed, declined, withdrawn or deleted (`requestAction`); a retainer decided or ended; a key result whose status a human sets, or that is met or missed by anyone; and a reset account's pending requests.
   - Test: `packages/core/test/asks.test.ts` › `a checkpoint, a retainer, an outbox request, a captain ask and an access request each file one ask, and the event that decides each retires it`
4. **A manager's own ask on a target retires with it too.** An ask a manager files with `ask` on a grant, a retainer or a key result is on that target, so the event that decides the target retires it like the town's own card; nothing reads prose to find out an ask is moot (the old digest's regex and the rollup readers are gone).
   - Test: `packages/core/test/asks.test.ts` › `the event that decides a target retires every live ask on it, a manager's own ask included`
5. **Only a human decides an ask; nothing decides one by silence.** `decideAsk` needs a human who can fund the ask's building, and records who, when and what (the branch label, plus the human's optional note as "<label>. <note>", up to 2000 chars; the ask's building manager hears it in their inbox). A request's do ask decides through the request itself (no Claim since 2026-11-12: Done takes the report back, Decline a note; the text after this describes the old Claim note) (kept as `requestNote`, sent to the agent author with the claim), Decline a required one (the server refuses a bare decline); `deferAsk` (a human or the Secretary) parks an open ask behind an event, and it stays listed in the Town Hall in-tray's `asks` (and counted in its badge) until decided or retired. When the ask or target id it waits behind is decided or retired, it is open again (`reopenDeferred`, `ask.reopened`). A decided ask is final.
   - Test: `packages/core/test/asks.test.ts` › `only a human who can fund decides an ask; a deferred ask stays listed until decided`
   - Test: `packages/core/test/asks.test.ts` › `a deferred ask opens again when the ask or the target it waits behind is decided or retired`
6. **A manager's card is checked before it is filed, and folds into the live ask on its target with its words.** `ask` (and `review` with `ask`) refuses, filing nothing, when a money ask names no grant or retainer or when a target does not exist (`checkAskCards` in `packages/core/src/asks.ts`). A card on a target that already has a live ask folds into it: a source line naming the entry that raised it, a fold in the history, and its words in place of the town's placeholder card.
   - Test: `packages/core/test/asks.test.ts` › `a manager's ask: refused when a money ask names no grant or retainer, or its target is not one of this town; a money ask folds into its grant's ask; one with no target is an ask of its own`
   - Test: `packages/core/test/ask-snapshots.test.ts` › `a manager's ask that folds into the item's live ask keeps its words on it: a source line naming its entry, a fold in the history; the decision answers every entry that raised it`
7. **The boot backfill is idempotent.** `backfillAsks` (World construction) files the ask of every open proposal (not a countered one: it waits on its manager), held grant, asked retainer, open request, pending captain and access request; a second run creates nothing.
   - Test: `packages/core/test/asks.test.ts` › `backfill files the asks of everything already open, and a second run creates nothing`
8. **An author's ask card is refused only for missing structure; style rules are warnings** (Mitchell, 1:1 mt_ewxnhs90cq decision 5, 2026-11-10: "i don't think we need the linter for text"). An author's card, a manager's `ask`, `propose_grant`'s card (the explorer's `ask`, else the one the town writes from the plan) or the Planner's `calibrate` card, is refused every time it lacks structure (`askStructure` in `packages/schema/src/ask.ts`, `refuseMissingStructure` in `packages/core/src/asks.ts`): two branches as buttons, the recommendation field, and its type's hard contract fields (money: prior decision, spent, steps; click: who is parked; credential: scope and fallback; meeting: the question; policy: the rule). There is no retry limit and no `ask.refused` event. Every other rule (sentence length, ids in the body, semicolons, parentheses, one instruction per sentence, condition first, ellipsis, dictionary words, and the soft contract fields: money claims, click permission, policy what-I-did and reversing cost) never refuses: `createAsk` files the card and records them as one `lint` history entry starting "warnings:", the author's answer names them, and no tag or pill marks the card. A card the town writes from a source's own words is filed the same way.
   - Test: `packages/core/test/ask-contract.test.ts` › `structure is the hard contract fields, two branch buttons and the recommendation field; the rest only warns`
   - Test: `packages/core/test/ask-contract.test.ts` › `an author's card missing structure is refused every time; style rules file it with warnings in its history`
9. **A claim's check result is never older than 5 minutes when shown.** `GET /api/asks/:id` re-runs an ask's mechanical claims (`pr`, `url`, `api`, and `kr` when its howToCheck is a curl or a URL) whose result is missing or older than `CLAIM_STALE_MS` before it answers (`runClaimChecks`, `packages/core/src/ask-checks.ts`); the server also runs them in the background when an ask is filed. A check that cannot run is stored as a failed result with its reason, never thrown.
   - Test: `packages/server/test/asks.test.ts` › `lists open asks, records what a signed-in human opens (never an agent), re-runs a stale claim check on open, and decides and defers`
   - Test: `packages/core/test/ask-checks.test.ts` › `runs pr, url, api and kr checks, leaves manual alone, stores the results and goes stale after 5 minutes`
10. **No ask title or body contains an ellipsis.** A card is written for the reader and never quotes the record (docs/legible-delegation.md §5): the town names a grant by its `title` (migration 105), never by its clipped objective, and the proposal card's second line is the first key result, dropped rather than clipped when it fails the linter. The linter's `no-ellipsis` rule refuses "…" in a title, body or recommendation, a manager's card too. At boot `retitleClippedAsks` rewrites every live town-written card that still carries one from its target, once, keeping its id, sources, rank and status; a card with no target card loses its ellipsis and keeps its words.
   - Test: `packages/core/test/grant-title.test.ts` › `the proposal card has no ellipsis, never quotes the objective, and its second line is the first key result`
   - Test: `packages/core/test/grant-title.test.ts` › `rewrites a live clipped town card once from its target, keeping its id, sources, rank and status; a card with no target card loses its ellipsis and keeps its words`
   - Test: `packages/core/test/grant-title.test.ts` › `refuses an ellipsis in an ask's title, body or recommendation`
11. **The Secretary's 1:1 carries the item open in the human's decision queue.** The queue PUTs the item on screen as the 1:1's `focus` (`PUT /api/meetings/:id/focus`, migration 106; only that 1:1's human, the same item twice writes nothing, null when the queue closes). Each of the human's lines reaches the agent with an "Open on <name>'s screen" block rebuilt from live data (`focusBlock`, `packages/core/src/meeting-focus.ts`): an ask decided or retired since it was opened says so, a gone id says gone. `act_in_1on1` with no target acts on that item, only on the human's cited words.
   - Test: `packages/core/test/meeting-focus.test.ts` › `listen carries the open item from live data: the ask's card, branches, status and target, then 'retired since it was opened'`
   - Test: `packages/core/test/meeting-focus.test.ts` › `act_in_1on1 with 'fund it' and no target decides the focused grant as the human`
   - Test: `packages/server/test/meeting-focus.test.ts` › `only the 1:1's human sets the open item; another human, an agent and a guest are refused; the same item twice is a no-op`
12. **Every live ask points at the entry that raised it** (`sourceEntryId`, migration 115; plan dc_uwx045472m step 6: an ask is a stored snapshot of a job's thread). A proposal's is its propose entry on the grant's job, a gate's the step report that forecast past the ceiling, a request's its do entry, a manager's `ask` or pass-up the entry it wrote; an ask raised with none (a retainer, a person asking to join or to captain, a rule) gets one on its building's thread, the Town Hall's when it has no building. At boot `rerenderAsks` names the entry of a live ask filed before the migration.
   - Test: `packages/core/test/ask-snapshots.test.ts` › `a proposal's ask: the propose entry on the grant's job; a request's: its do entry; a retainer's and a join request's: an entry on the building's or the Town Hall's thread`
   - Test: `packages/core/test/ask-snapshots.test.ts` › `boot: a live ask filed before migration 115 gets the entry it came from, once`
13. **A card the town writes follows its thread; a card with an author's words is marked when its thread moves.** When an entry lands on a job's thread, `rerenderAsks` writes again every live town card raised there from its object as it now stands, and records the thread's length in `renderedSeq`. A card whose words are a manager's or the Secretary's keeps them; `entriesSinceCard` counts how far its thread has moved, the Secretary's `rank` read marks it THREAD MOVED, and `rank` `rewrite` (the Secretary only) writes its title, body or recommendation again, never its type, branches or target.
   - Test: `packages/core/test/ask-snapshots.test.ts` › `a town card is written again from its object when an entry lands on its thread, and its renderedSeq moves with the thread`
   - Test: `packages/core/test/ask-snapshots.test.ts` › `an author's card keeps its words and is marked behind its thread; the Secretary's read says so, and rewrite writes it again`
14. **A request for a human is a do ask: Done or Decline, never Claim, and it sorts last** (1:1 mt_msnjkpgwdb decisions 16-17). `request_human` needs `worth`; the `do` contract refuses a card without it; a boot repair (`requestsToDoAsks`) reopens claimed requests and rewrites their asks; an unranked do ask sorts after every other unranked ask; the Secretary may not close one as overtaken.
   - Test: `packages/core/test/asks.test.ts` › `boot repair: a claimed request is open again and its ask offers Done / Decline as a do; a second run changes nothing`
   - Test: `packages/core/test/asks.test.ts` › `an unranked do ask sorts after every other unranked ask, whatever its age`
   - Test: `packages/core/test/verbs.test.ts` › `open → done (no claim: 1:1 mt_msnjkpgwdb decision 17) creates a library human-report, answers its entry on the thread and notifies the agent`
15. **A human's decision on an ask wakes one Secretary run, debounced; an agent's act wakes none.** `decideAsk`, and `retireAsks` when a human's decision retired the ask, call `Secretary.afterDecision` (packages/core/src/secretary.ts): one pending run at a time, a line added per decision while it waits, at most `DECISION_RUNS_PER_DAY` a day, none while the ranking retainer is not approved, the Secretary is stopped or no ask is left open (1:1 mt_msnjkpgwdb decision 10).
   - Test: `packages/core/test/secretary-decisions.test.ts` › `the first decision queues one run on the ranking retainer that waits out the debounce; decisions meanwhile add a line, not a run`
   - Test: `packages/core/test/secretary-decisions.test.ts` › `a decision while a run is under way queues one more; nothing is queued with the retainer unapproved, the Secretary stopped, or no ask left open`
   - Test: `packages/core/test/secretary-decisions.test.ts` › `at most DECISION_RUNS_PER_DAY runs a day draw on the ranking retainer: past the cap a decision waits for the next ranking`
   - Test: `packages/core/test/secretary-decisions.test.ts` › `an agent's or the town's act is not a human decision: a manager withdrawing its proposal queues nothing`
16. **The Secretary closes only a click or policy ask as overtaken, never a money, credential or meeting ask nor a request a human must carry out**, and what it closes its building hears on its thread. `maySettle` and `overtakeCandidates` (packages/core/src/overtake.ts) are pure; `overtakeAsk` (packages/core/src/asks.ts) is the only writer, and a call that names one ask it may not close changes nothing (decisions 10 and 20a).
   - Test: `packages/core/test/overtake.test.ts` › `maySettle: only a live click or policy ask that is not a request a human must carry out`
   - Test: `packages/core/test/overtake.test.ts` › `property: every candidate is settleable, is not the decided ask, and is tied to the decision (same item, or names it)`
   - Test: `packages/core/test/secretary-decisions.test.ts` › `overtaken closes a click ask with the note, tells its building on its thread, and reopens what was deferred behind it; one call can also re-rank`
   - Test: `packages/core/test/secretary-decisions.test.ts` › `it never closes a money, credential or meeting ask, nor a request a human must carry out; a refused call changes nothing`
